# Wasteland Harvest — Full Project Audit (2026-10-07)

Written at the start of the "make it a great game" push, after reading the docs and code,
running every test and smoke tool, and rendering the real game under a virtual display.
Verdicts are deliberately blunt: the point of this document is to find what stands between
the current build and a game people would actually enjoy.

The report is accurate about *systems*. What it does not say — and what matters most — is how
the game looks, sounds and feels to play. That is where nearly all of the remaining distance is.

## 2. What is genuinely good (keep it)

- **Architecture.** Pure static rule functions (`farm_grid.gd`, `npc_grid.gd`, `wang_tileset.gd`,
  `save_data.gd` codecs) with thin stateful nodes on top; signal-based wiring in `main.gd`;
  a shared modal gate; a versioned, additive save format; zones as always-instantiated siblings.
  This is sound, testable, and fast to extend. **No rewrite is warranted.**
- **Test discipline.** A custom headless runner, 388 unit tests, and real end-to-end drivers that
  push simulated input through the actual scenes.
- **Design documents.** `GDD.md` is a genuinely strong design: clear tone contract (cozy town,
  dangerous ruins), a coherent world, a good ammo-scarcity idea, a faction with real stakes.
- **Character art.** The PixelLab player + 4 NPCs (idle/walk, 4 directions) are decent and
  stylistically coherent with each other.
- **Night rules and save hygiene** (2 AM pass-out, save-on-sleep, time pause in menus).

## 3. Brutal assessment — what a player would actually experience

### 3.1 It does not look like a game yet (presentation: **2/10**)
Screenshots of every zone show:
- **Wallpaper grass.** One grass tile, repeated across a 72×32 farm. No variation, flowers,
  tufts, paths, shading or decoration. Every zone is a bright green field.
- **Placeholder objects.** Trees and ore nodes are *flat-colour 12×12 squares* (`farm.gd`
  `_spawn_resource_prop` → `ColorRect`). The farm reads as a field of brown and grey squares.
- **Fences and water are the same "rubble" tile tinted** (`test_map.gd` FENCE_TINT/WATER_TINT).
  Fences read as black voids; ponds read as blue brick walls.
- **Scale and perspective mismatches.** Buildings are drawn in a rotated, isometric-ish view
  (the ranch house is visibly on a diagonal) on a flat top-down grid. The farmhouse is 48×32 px
  — barely taller than the player. Goats and cows are larger than people.
- **18 of 27 items have no icon** — the hotbar shows 3-letter codes ("Hoe", "Wtr", "SdP").
- 8 of 18 buildable structures have no art (flat colour boxes).
- No animation in the world: no swaying crops, no water, no particles, no weather.

### 3.2 It is completely silent (audio: **0/10**)
`audio/` is empty. No music, no ambience, no tool sounds, no UI sounds. A farming game is
largely *felt through sound*; this is the single cheapest large improvement available.

### 3.3 Interaction feel (controls: **4/10**)
- Keyboard only. No mouse targeting, no mouse UI, no controller.
- No target-tile highlight: the player never sees which tile the next swing will hit.
- One button (Space/E) is both "use tool" and "talk/open"; pressing it near a chest while
  holding a hoe opens the chest.
- No feedback on actions: no particles, no sounds, no floating "+3 Wood", no screen shake,
  no hit-stop. Chopping a tree removes a square instantly in one hit.
- Movement itself is fine (56 px/s, 4-dir facing with horizontal bias, hold-to-repeat tools,
  till-and-advance).

### 3.4 The farming loop is thin and punishing (core gameplay: **3/10**)
- **Missing one day's watering kills a crop outright** (`farm_grid.gd advance_plot`). Stardew
  simply pauses growth. This breaks the GDD's own cozy contract and is the worst rule in the game.
- Watered state is a blue tint on the *plant*, not darker wet soil.
- 4 crops, single harvest, no seasons, no regrowth, no quality, no fertiliser use (the item
  exists, nothing consumes it), no sprinklers, no tool upgrades.
- The Open Plains farm starts with **768 pre-tilled cells**. There is no land-clearing arc —
  the most satisfying early Stardew loop (clear debris → reclaim the farm) is absent.
- Resources (trees/ore) never respawn; once cleared, wood and stone are gone forever except
  via one building's trickle.

### 3.5 Nothing to work toward (progression/goals: **2/10**)
- No skills, no XP, no tool upgrades, no crafting, no quests, no journal, no story beyond one
  Day-28 conversation.
- Buildings have marginal effects (+1 scrap/day, +10 max energy) and are mostly invisible
  (placeholder art).
- Each NPC has **one fixed conversation** (Marta: 3 nodes) that repeats forever, and Harlan
  greets the player as "the new farmer" — contradicting the GDD's premise that the player grew
  up in this town.

### 3.6 Half the game does not exist (expeditions/combat: **0/10**)
The ruined city, combat, enemies, loot, radiation, raider faction — the entire "wasteland
outside the fence" pillar that gives the cozy side its meaning — has not been started.

### 3.7 World structure (content: **3/10**)
Town is a 36×17 field with a mayor's house, a store, four identical shacks and a pond. No
interiors, no plaza dressing, no paths, no lamps, no market, no clinic. Four zones total.

## 4. Technical risks and debts found

| Item | Severity | Note |
|---|---|---|
| Crop death on one dry day | High (design) | Fix in Milestone A. |
| `test_map.gd` paints only grass/soil Wang + tinted rubble | High (visual) | Replace with a layered dual-grid terrain painter (grass base + path/soil/water/etc. overlay layers). |
| Resource nodes are `ColorRect`s, single-hit, never respawn | High | Replace with a world-object system (HP, drops, respawn, sprites). |
| One input action for tool + interact | Medium | Add a separate `interact` action and mouse targeting; keep `use_tool` contextual for compatibility. |
| No audio bus layout / audio manager | Medium | Add `AudioManager` autoload with Music/SFX/Ambience/UI buses. |
| Comments carry long phase-history narratives | Low | Readable but slow; new code uses shorter docs. Not worth a churn pass. |
| `.uid` files for 20 scripts never committed | Low | Committed in this push. |
| PixelLab API blocked by the cloud environment's egress policy | Process | New art is code-generated (Python + PIL pipeline in `tools/art/`) until access is granted. |

## 5. Conclusion

The foundation is better than most prototypes at this stage — clean code, real tests, a strong
design. But as a *game*, it is currently a silent, placeholder-art farming prototype with a thin
loop, a punishing core rule, no goals, and no second pillar. The fastest route to "people would
enjoy this" is **not** to keep ticking the old phase list in order. It is:

1. Make the first hour feel great: feedback, sound, music, readable art, a forgiving and deeper
   farming loop with land to reclaim.
2. Give every day a reason: seasons and weather, crafting, skills, tool upgrades, requests and a
   settlement-rebuilding project line with visible results.
3. Build the ruins: combat, enemies, loot and extraction — the contrast the whole game is built on.
4. Then breadth (NPCs, events, festivals, economy) and polish (UX, options, accessibility, export).

The accelerated plan implementing this lives at the top of `ROADMAP.md`.
