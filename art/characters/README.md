## `rancher_silas/` — Phase 8 Ranch/Sanctuary keeper NPC

Silas, the Ranch/Sanctuary compound's keeper (`ROADMAP.md` Phase 8, `GDD.md` §8/§11) — spawned
with full dialogue but no buy-animal transaction yet (that's gated on the Barn/Coop building
split, still open). Same pipeline as the town-core NPCs below: `mcp__pixellab__create_character`
standard mode, 16px character on a 24x24 canvas, 4 directions, `low top-down` view, basic
shading, single color outline, low detail — then `mcp__pixellab__animate_character` with
templates `walking-4-frames` and `breathing-idle` (all 4 directions each), matching this repo's
established idle+walk-only NPC scope (no tool_* set — Silas doesn't use tools).

- **Rancher Silas — character id `c8dd77da-5f26-4642-9b07-20ddbda6f223`** ("NPC - Rancher
  Silas"). No v2/rejected attempt on the account for this character — a single accepted
  generation. Confirmed by downloading the `south` rotation from the PixelLab account and
  matching its SHA-256 hash byte-for-byte against the shipped `rotations/south.png`.

### Files

Same layout as `mayor_harlan/`, `marta/`, `scout_kael/`, and `player/` below:

- `rancher_silas/rotations/{south,north,east,west}.png` — base directional stills (24x24).
- `rancher_silas/walk/{dir}/{0-3}.png` — walk cycle, template `walking-4-frames`.
- `rancher_silas/idle/{dir}/{0-3}.png` — idle, template `breathing-idle`.

## `mayor_harlan/`, `marta/`, `scout_kael/` — Phase 6 "Art pass 1" NPCs

The 3 town-core NPCs (ROADMAP Phase 6 "Art pass 1"; previously flat-color ColorRect
placeholders built in scripts/npc.gd), generated through the exact pipeline the player
established below: `mcp__pixellab__create_character` standard mode, 16px character on a
24x24 canvas, 4 directions, `low top-down` view, basic shading, single color outline, low
detail — then `mcp__pixellab__animate_character` per character with templates
`walking-4-frames` and `breathing-idle` (all 4 directions each).

- **Mayor Harlan — character id `dcb351f7-384f-4234-b907-7939fcfbfdc6`** ("NPC - Mayor
  Harlan"). Older founder-authority read: grey hair/stubble, heavy worn-wood-dark coat
  `#7b5025` (his npc.gd placeholder identity color) over a worn cream shirt `#ffedb1`.
- **Marta — character id `d3193faa-ca86-41ee-857e-7df8b0294070`** ("NPC - Marta").
  Practical shopkeeper warmth: dark hair in a bun, lamplight-gold apron `#ffc948` (her
  identity color) over a dusty-amber/red blouse. The generation gave her a faint
  spectacles band across the eyes on every south-facing frame — consistent across the
  whole south set, so it reads as a deliberate design detail (shopkeeper glasses) and
  was kept.
- **Scout Kael — character id `4fe49946-1b70-4661-8a47-140649d03972`** ("NPC - Scout
  Kael"). Road-worn watcher: short dark hair, scavenged grey-tan scarf/cloak `#9d9180`
  (his identity color) over a deep-leaf-green shirt `#5d7d3a`, red neck scarf.
- A v2 attempt per character (ids `39433cf7…`, `861b9d20…`, `f3bc8adb…`, named "… v2")
  tried prompt-forcing correct back views and overshot — every view lost its face,
  fronts included. Rejected; left on the PixelLab account, not used.

**Animation scope (judgment call):** idle + walk only, all 4 directions. These NPCs never
use tools (wander + dialogue only, per scripts/npc.gd), so no tool_* set was generated —
that's not a gap for Phase 7 to fill so much as a cost call to revisit only if schedules
ever animate work actions. All 4 directions are fully animated because npc.gd's wander can
face any cardinal direction; under-covering one would visibly break mid-wander.

**Back-view repair (same class of fix as the player's below):** PixelLab painted face/skin
pixels onto several north (back) frames for all 3 NPCs (and a blue smear onto two of
Harlan's idle-south faces). Fixed in place with pixel surgery — skin-in-head-box recolored
to each frame's sampled hair color, and where a face flickered in/out across an animation,
the head region copied from a clean back frame of the same animation. Rotations got the
same fix for consistency even though only idle/walk frames are referenced at runtime.

### Files (per NPC, same layout as `player/`)

- `<name>/rotations/{south,north,east,west}.png` — base directional stills (24x24).
- `<name>/walk/{dir}/{0-3}.png` — walk cycle, template `walking-4-frames`.
- `<name>/idle/{dir}/{0-3}.png` — idle, template `breathing-idle`.
- `<name>/<name>_frames.tres` — Godot `SpriteFrames` (generated by
  `tools/build_player_frames.py`, now generalized over all characters): animations
  `idle_*`/`walk_*` per direction, walk at 6 fps (not the player's 8 — NPCs amble at
  24 px/s vs the player's 56, and the slower cycle matches). Consumed by scripts/npc.gd's
  runtime-built AnimatedSprite2D (`NPC_FRAMES`).

## `player/` — Phase 2 player character

One representative player character proving the movement/animation pipeline (ROADMAP Phase 2).
This is deliberately NOT the full preset-portraits-plus-cosmetic-sliders character-creation
system from `GDD.md` §3 — that's later birth-sequence/UI work — and it's placeholder-tier art
until Phase 6's "Art pass 1" (which explicitly re-does the player character).

Generated via `mcp__pixellab__create_character` (standard mode, 1 generation):

- **Character id `6ee1466d-dd09-4732-9e99-ad57c9efbfab`** ("Player - Wastelander Farmer v2"),
  16px character on a 24x24 canvas, 4 directions, `low top-down` view, basic shading, single
  color outline, low detail. Judgment call on view: tiles are `high top-down` but the character
  uses `low top-down` (classic 3/4 RPG look) — this is Stardew's actual mix (flat floors,
  forced-perspective characters), per CLAUDE.md's projection note.
- Description: young adult wasteland settler farmer in the settlement anchor palette
  (`GDD.md` §9 — dusty amber jacket `#c9974b`, faded green undershirt `#8a9a56`, worn wood
  brown trousers `#6e5033`).
- A first attempt (id `54624216-c898-4a40-80d4-1a482bd11dbe`, "Player - Wastelander Farmer")
  painted frontal shirt details on the north/back view and was superseded by v2; v2's back
  view still showed skin under the hair. v1 is left on the PixelLab account (not deleted)
  in case the orchestrating session prefers its outfit detail.
- **Fixed in Phase 6's Art pass 1 (as this note promised):** on inspection the issue was
  worse than the "sliver of neck/ear skin" recorded above — idle/north/2, walk/north/1-2,
  and all five tool/north frames had actual face patches (including eye-white pixels), so
  walking north visibly flickered face-in/face-out. All 14 north-facing PNGs (rotations +
  idle + walk + tool) were repaired in place: opaque non-hair pixels inside the head box
  (rows 4-8, cols 8-15) recolored to each frame's modal hair color, keeping row 9's
  legitimate neck line and the tool swing's raised hands (outside the box). 98 px total
  across 10 frames. player_frames.tres references the PNGs by path, so no .tres change.

### Files

- `player/rotations/{south,north,east,west}.png` — base directional stills (24x24 each).
- `player/walk/{dir}/{0-3}.png` — walk cycle, template `walking-4-frames` (1 gen/direction).
- `player/idle/{dir}/{n}.png` — idle, template `breathing-idle` (1 gen/direction).
- `player/tool/{dir}/{n}.png` — tool-use stub swing, v3 custom animation from an
  action description (1 gen/direction). Phase 3 attaches real tool effects to it.
- `player/player_frames.tres` — the Godot `SpriteFrames` consumed by
  `scenes/player.tscn`'s AnimatedSprite2D: animations `idle_*`, `walk_*`, `tool_*` per
  direction; `tool_*` are non-looping (scripts/player.gd waits on `animation_finished`
  to unlock movement).
- `player/regions/{action}/{dir}/{n}.png` — Milestone E recolour masks, one per frame (red
  hair, green skin, blue outfit), code-generated by `tools/art/opening/op_regions.py`; the
  character-creation palette swap (`scripts/player_look.gd`) reads them. Rebuild them whenever a
  player frame changes (`python3 tools/art/opening/build.py regions`).

## Enemies (code-generated) — Milestone C

`enemies/<id>.png` for `shambler`, `runner`, `raider`, `bloater`, `rad_hound` are drawn by code,
not PixelLab: `python3 tools/art/enemies/build.py` (package `tools/art/enemies/`; deterministic,
re-running gives byte-identical PNGs). Colours come from `tools/art/palette.py` (the
"Enemies / combat FX" block). The same build writes the combat FX in `art/fx/` and the HUD icons
`art/ui/hp_icon.png` / `art/ui/rad_icon.png`.

**Sheet format** (the game slices by these coordinates): 24x24 frames, 4 columns x 14 rows =
**96x336**.

| rows | content |
|------|---------|
| 0-3 | idle S, N, E, W — 2 frames (cols 2-3 transparent) |
| 4-7 | walk S, N, E, W — 4 frames |
| 8-11 | attack S, N, E, W — 4 frames: 0 windup start, **1 windup peak = the dodge telegraph**, 2 strike, 3 recover |
| 12 | hurt — col 0 S, 1 N, 2 E, 3 W |
| 13 | death — 4 frames, direction-agnostic; frame 3 is the corpse left on the ground |

W frames are mirrors of E. Same canvas and anchoring as the player: the figure is centred on
column 12 and **the lowest opaque row of every standing frame is row 20** (the player's feet
row; body pixels end on row 19, the 1 px cold outline sits on row 20). The build asserts this,
plus 96x336 and no pure black. No contact shadow is baked in (the player/NPC frames have none
either). Translucent pixels appear only in the bloater's warning glow and belch gas.

Telegraphs: shambler throws both clawed arms over its head, jaw open; runner cocks one claw high
and shrieks; raider locks the pipe pistol out (S view: elbows out, gun centred on the chest;
frame 2 is the kick, the muzzle flash is the separate `art/fx/muzzle_flash.png`); bloater
swells to ~21 px with white-hot pustules and a rad-green halo, then belches gas on frame 2;
rad-hound coils low with hackles up and fangs bared, then lunges.

Review aids: `enemies/_preview.png` (all sheets at 3x beside the player) and
`enemies/_preview_anim/<id>.gif` (walk S, attack S, death; Godot-ignored).

## Townsfolk (code-generated) — `brask/`, `wren/`, `doc_ama/` (Milestone B)

The three new named NPCs from `docs/SOCIAL_AND_QUESTS.md` §1 are drawn by code, not PixelLab
(its API host is blocked in this environment): `python3 tools/art/townsfolk/build.py characters`
(package `tools/art/townsfolk/`, also run by `tools/art/build_all.py townsfolk`; deterministic,
re-running gives byte-identical PNGs). Colours: the "Townsfolk and Town Works" block in
`tools/art/palette.py`. House rules: `docs/ART_STYLE.md` §8.

- **Brask** (`tf_brask.py`) — grey crew cut, scar through his left eyebrow (shows facing south and
  west), olive-drab long coat with square shoulders and a belt, dark trousers, tall boots, a short
  cudgel on his right hip.
- **Wren** (`tf_wren.py`) — patched brown hood over auburn hair, brass goggles pushed up on her
  forehead, muted teal scarf, faded plum jacket, satchel strap from her left shoulder to the bag on
  her right hip, fingerless gloves, patched khaki trousers.
- **Doc Ama** (`tf_doc_ama.py`) — dark hair greying at the temples in a bun, round glasses that
  catch the light, long off-white coat, red armband on her left sleeve, satchel on her right hip.

Same layout and anchoring as the PixelLab NPCs above, so nothing downstream differs:
`<id>/rotations/{dir}.png` (= idle frame 0), `<id>/idle/{dir}/{0-3}.png` (a 1 px breath),
`<id>/walk/{dir}/{0-3}.png` (4-frame stride with a 1 px bob), 24x24, figure centred, lowest opaque
row 20. West frames are mirrored east frames except for one-sided gear, which is redrawn for the
left flank. `<id>/<id>_frames.tres` comes from `tools/build_player_frames.py` (idle 5 fps, walk
6 fps, like the other NPCs; its provenance comment says "code-generated (tools/art/townsfolk)").
Review sheet: `townsfolk_preview.png` (Marta and Harlan above the three, idle in four directions
plus the walk south / east cycles, x5).
